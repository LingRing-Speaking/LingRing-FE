# Android 통화·녹음 QA 체크리스트 (#165 / #168)

Web 경로(WebView 표준 WebRTC) + `MediaRecorder` 녹음 설계의 **실기기 검증** 목록.
이 환경엔 Android SDK/기기가 없어 자동 검증이 불가하므로, 아래는 사람이 기기에서 확인한다.

## 0. 준비물

- [ ] Android Studio + 실기기 2대(또는 기기 1 + 다른 플랫폼 1)로 1:1 매칭
- [ ] 기기 **System WebView**(Chromium) 최신화 (Play 스토어) — `MediaRecorder`/getUserMedia 의존
- [ ] BE dev 환경 통화 매칭 가능 상태
- [ ] 빌드: `npm run build:android:dev` → `npx cap open android` → 기기 실행

## 1. 빌드·실행 (#164 회귀)

- [ ] `build:android:dev` 빌드/설치 성공
- [ ] 앱 실행 → 스플래시 → 로그인 화면에 **애플 버튼 없음(카카오만)**
- [ ] 카카오 로그인 성공 (콘솔 키 해시 미등록이면 여기서 실패 — #166 콘솔 작업 확인)

## 2. 마이크 권한 & 통화 연결 (#165)

- [ ] 통화 시작 시 **마이크 권한 팝업이 1회 노출**되는가
  - ⚠️ 팝업이 안 뜨고 통화가 무음이면 → Capacitor 자동 권한 처리가 안 되는 환경. "런타임 권한 요청 글루 코드" 후속 필요 신호 → 로그 첨부해 공유
- [ ] 권한 허용 후 두 기기가 **"연결됨"** 상태 도달
- [ ] 양방향 음성이 정상으로 들림
- [ ] 음소거 토글이 실제로 내 마이크를 끔(상대가 못 들음)
- [ ] (참고) 이어피스/스피커 라우팅·블루투스는 **#55** 범위 — 본 QA 제외

## 3. 녹음 → 분석 (#168) — 핵심

- [ ] **1분 이상** 통화 후 종료
- [ ] 통화 기록 화면에서 **분석하기 버튼 활성화** (durationSec ≥ 60)
- [ ] 분석 요청 → 결과가 정상 표시됨
- [ ] 분석 결과가 **"내 발화" 기준**인가 (상대방 목소리가 아님 — iOS와 동일하게 로컬 마이크만 녹음)
- [ ] 업로드 흐름 정상: presign 200 → S3 PUT 200 → createRecording 200 (WebView 콘솔/네트워크 확인)

## 4. 엣지 케이스

- [ ] 통화 중 앱 백그라운드 → 복귀 시 음성 복구되는가
- [ ] **1분 미만** 통화 → 분석 버튼 비활성 (기존 정책 유지)
- [ ] 통화 종료 직후 즉시 화면 이탈해도 업로드가 끝까지 진행되는가 (fire-and-forget)
- [ ] 통화 중 앱 강제 종료(스와이프) → 다음 실행 정상. 단 **그 통화 녹음은 미복구**가 정상 동작 (Android v1은 디스크 보존 없음)
- [ ] 업로드 중 네트워크 끊김 → 앱이 멈추지 않고 분석 실패가 자연스럽게 안내되는가 (Android v1: 재시도 없음)

## 5. 설계 변수 — QA 중 반드시 확인

- [ ] **BE STT가 webm/opus 를 실제로 디코딩**해 의미 있는 분석을 내는가
  - 업로드는 되는데(화이트리스트 통과) 분석 결과가 비거나 이상하면 → 코덱 문제. 트랜스코딩 또는 포맷 변경(wav 등) 후속 필요
- [ ] presign/S3 가 `content-type: audio/webm` 으로 정상 통과하는가 (서명 불일치 403 없는지)

## 로그 수집 팁 (실패 시 첨부)

- WebView 콘솔: `chrome://inspect` 연결 → `[callRecorder]` / `[recordingUploader]` 경고 확인
- 네이티브: `adb logcat | grep -iE "audio|permission|webrtc"`
